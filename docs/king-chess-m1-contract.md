# 国王棋 · M1 实现契约（岚中对 · 热座可玩）

- **状态**：已冻结（本轮开发的唯一契约来源）
- **上游**：`docs/king-chess-design.md`（设计侧）＋《国王棋游玩手册》（甲方 PDF，本仓库根目录，未入库）
- **下游**：`backend/.../kingchess/**`、`frontend/src/views/ChessView.vue`
- **铁律**：裁决只在后端。前端只发请求、只渲染视图，不得自行判定吃子 / 计分 / 胜负 / 随机。

> 凡手册模糊之处，本文件给出**实现方默认**，逐条以 `DEFAULT:` 标注。开发时在对应代码处写注释指回本节编号。

---

## 1. M1 范围

- 2–4 人**热座**（同一浏览器轮流操作各座位），后端持有权威对局状态。
- 完整回合流：刷新公棋 → 秘密落子 → d20 定序 → 落子互吃 → 特殊效果轮 → 计分 / 胜负。
- 会话存内存 `Map<gameId, KingGame>`，不落库（M1 明确不做持久化与断线续玩）。
- 不做：在线多人、SSE 推送、AI 对手、格栏玩法、非岚中对棋局。

## 2. 规则冻结

### 2.1 座位与棋场

- 4 个方位 `NORTH / EAST / SOUTH / WEST`，各一个棋场，**每场 4 格**（`cellIndex` 0–3）。
- 座位按顺时针映射方位：`seat 0 → NORTH`，`seat 1 → EAST`，`seat 2 → SOUTH`，`seat 3 → WEST`。
  - `DEFAULT-1`：2 人局取 `seat 0/1`；3 人局取 `0/1/2`。
- **落子不限于自己的棋场**：任何玩家可把棋子放到任意棋场的任意空格。
  （手册只说「决定你要放多少棋、落在哪里」，现有测试也已确立该语义。）

### 2.2 箭头环

- 每个棋场的 4 格构成环：`0 → 1 → 2 → 3 → 0`（`DEFAULT-2`，甲方 2026-09-09 已确认「顺着箭头循环」）。
- 马前进沿该环走一格；越界回绕。
- 甲方已确认：**不得触发循环冲突**（沿环移动不得产生无限循环或自相矛盾的占位）。

### 2.3 棋子与归属

**私棋**（每玩家每种 1 枚，初始全在手）

| 棋子 | 规则 |
| --- | --- |
| 国王 KING | 吃任何棋 **+3 分**；被吃后**回手**并**扣 1 条命**（初始 5 条）；命尽（=0）则不再回手。 |
| 王后 QUEEN | 被吃后**其拥有者 +8 分**（甲方确认，纠正手册「rd12」笔误）；其余情况无分。 |
| 死士 MARTYR | 在其拥有者场上的期间，该玩家所有棋子受保护：己方棋子被吃时，改为**死士被吃**（下场），攻击者占死士所在格。`DEFAULT-3`：不连锁，仅替换站位。 |
| 谋士 STRATEGIST | 在特殊效果轮中，其拥有者可**收回场上任意一颗自己的棋子**回手。 |

**公棋**（每场共 24：8 粮草 / 6 兵 / 4 马 / 4 车 / 2 骑士，全部存放在棋局）

| 棋子 | 被吃时 |
| --- | --- |
| 粮草 PROVISION | 吃者 **+4 分**；棋子**回收到棋局**。 |
| 兵 SOLDIER | 吃者 **+2 分**；棋子**归吃者手牌**（可再放置）。 |
| 马 HORSE | 吃者 **+0 分**；棋子**归吃者手牌**。 |
| 车 CHARIOT | 吃者 **+0 分**；棋子**归吃者手牌**。 |
| 骑士 KNIGHT | 吃者 **+0 分**；棋子**归吃者手牌**。 |

- `DEFAULT-4`：手册「除特别标记外，被吃的公棋都会被回收到棋局」，而兵 / 马 / 车 / 骑士明确写「吃掉获得该棋子」，故这四种**进吃者手牌**而非回收棋局。
- 国王吃任何棋**固定 +3**，覆盖被吃棋自身的分值（即使吃的是粮草也只 +3，粮草仍按上表处理）。

### 2.4 手牌与「无棋可用」

- 初始手牌：`[KING, QUEEN, MARTYR, STRATEGIST]`。
- 落子时从手牌取出该枚棋子，落到场上（**从手牌移除**）。
- 私棋被吃即**永久下场**（国王除外，见上）。
- `DEFAULT-5`：设计文档 §4.5「私棋放置次数无限制」理解为**每轮可放置的枚数不限**（受手牌存量约束），而不是无限供应；否则「无棋可用」永不成立。
- 回合开始（进入 PLACING）时逐位检查：**手牌为空即视为「无棋可用」**——场上是否还有己方棋子不影响判定（手牌空就再也无法落子，若还要求场上也无棋，双方会永远无法行动、对局死锁）。此时国王**自动回手**并**扣 1 条命**：若国王此刻还在场上，先收回手中，保证任一时刻国王实例唯一；若国王命数已为 0，则该玩家**失败出局**（`eliminated`）。

### 2.5 一轮流程

```text
1. 刷新公棋（公开）：全场合计随机刷新 1–5 枚（DEFAULT: 数量走 DiceRoller.between(1,5)），
   按 SPAWN_WEIGHTS 加权抽取棋种，受棋局余量限制；随机落到四个棋场的空格；空位不足则少刷。
2. 秘密决策：各座位提交本轮部署（落几枚、落在哪个棋场哪一格）。各座位提交互不可见。
3. d20 定序（公开）：每人掷 1d20，点数大者先落；平手按座位号升序（DEFAULT-6）。
4. 落子互吃（公开）：按序落子；同一格「后落吃先落」。
5. 特殊效果轮（公开，统一至多 16 秒）：马前进 / 车移动 / 骑士收回 / 谋士收回 / 死士保护。
6. 计分与收尾：按 §2.3 结算；结算胜负（≥50 分，或其余玩家全部出局）。
```

### 2.6 特殊效果轮细则（`DEFAULT-7`：逐项线性结算，先公棋后私棋，每枚棋子每轮至多触发一次）

| 效果 | 触发者 | 目标 | 结算 |
| --- | --- | --- | --- |
| `HORSE_STEP` | 场上一枚**自己的马** | 无 | 沿箭头环前进 1 格；目标格被占则本回合不移动。 |
| `CHARIOT_MOVE` | 场上一枚**自己的车** | 同棋场内任意**空格** | 移动过去；不能出棋场。 |
| `KNIGHT_RECALL` | 场上一枚**自己的骑士** | 无 | 收回手牌。`DEFAULT-8`：若该骑士本轮是被速度（d20）高于自己的玩家吃走后归其所有，则已不属于你，无从收回。 |
| `STRATEGIST_RECALL` | 场上一枚**自己的谋士** | 场上任意一枚**自己的棋子** | 该棋子收回手牌。 |
| 死士保护 | 场上有**自己的死士** | 无 | 被动生效，见 §2.3，不占用行动。 |

- `DEFAULT-9`：16 秒为前端展示层的统一倒计时；后端只收集动作、**全员提交后统一结算**，不逐秒驱动。超时由前端以「空动作」提交。
- 结算顺序：先处理全部 `HORSE_STEP` 与 `CHARIOT_MOVE`（移动类），再处理全部 `*_RECALL`（收回类）。同玩家多动作按提交顺序执行。

### 2.7 胜负

- 任一玩家 **≥50 分** → 立即胜出。
- 或：**只剩一名玩家未出局** → 该玩家胜出。
- `DEFAULT-11`：若**全部玩家在同一轮出局**（无存活座位），判为**平局** —— `phase = FINISHED`、`winnerSeat = null`，**绝不回到 PLACING**。手册与设计文档都没有「全员尽墨」的规则，因此不发明「分数高者胜」的裁定；前端需把 `winnerSeat === null` 渲染为平局，而不是当作错误。
- 结束后 `phase = FINISHED`，后续**任何写操作**一律拒绝。

## 3. REST API 契约

基础路径 `/api/kingchess`，全部需要 JWT（与 `/api/**` 一致）。错误统一抛 `BusinessException`。

### 3.1 创建对局

```http
POST /api/kingchess/games
{ "playerCount": 2 }        // 2..4
→ 200 KingGameView
```

### 3.2 查询对局

```http
GET /api/kingchess/games/{gameId}
→ 200 KingGameView
```

### 3.3 提交部署（覆盖式）

```http
POST /api/kingchess/games/{gameId}/deployments
{
  "seat": 0,
  "deployments": [
    { "side": "NORTH", "cellIndex": 0, "pieceKind": "SOLDIER" },
    { "side": "WEST",  "cellIndex": 2, "pieceKind": "KING" }
  ]
}
→ 200 KingGameView
```

- 同一座位重复提交 = **整份覆盖**（幂等重填），不是追加。
- 校验：`side` 合法、`cellIndex ∈ 0..3`、`pieceKind` 在该座位手牌中、**同一座位内**不得把多枚棋子放到同一个 `(side, cellIndex)`。
- **跨座位同格必须允许**：多人争夺同一格正是「后落吃先落」（§2.5-4）的唯一来源，绝不可在校验层拦住。
- 允许提交空数组（表示本轮不落子）。
- **保密（强制）**：响应中的 `fields` **不得**包含本轮未结算的落子，必须保持提交前的棋盘状态；进度只由 `submittedSeats` 表达。手册明写「每个人的行动轮决策都是秘密进行的，你不能得知其他人的落子处在何地」——将已提交的落子渲染进响应，会让热座切换座位时直接偷看。

### 3.4 结算本轮（掷 d20 + 落子互吃）

```http
POST /api/kingchess/games/{gameId}/resolve
→ 200 KingGameView
```

- 要求全部**在场**（未出局）座位均已提交过部署（未提交 → 400）；出局座位不参与提交，也不计入该判断 —— 否则 3/4 人局首次出局后本轮将永远无法结算。
- 结算后 `lastRolls` / `lastDropOrder` / `events` 填充；`phase` 变为 `EFFECTS`（若有人有可执行效果）或 `ROUND_END`。

### 3.5 提交特殊效果动作（覆盖式）

```http
POST /api/kingchess/games/{gameId}/effects
{
  "seat": 0,
  "actions": [
    { "type": "HORSE_STEP",       "pieceId": 12 },
    { "type": "CHARIOT_MOVE",     "pieceId": 5, "targetCellIndex": 2 },
    { "type": "KNIGHT_RECALL",    "pieceId": 7 },
    { "type": "STRATEGIST_RECALL","pieceId": 9, "targetPieceId": 3 }
  ]
}
→ 200 KingGameView
```

- 仅 `phase = EFFECTS` 时接受。
- 全员提交后**服务端立即统一结算**（先移动后收回），随后 `phase = ROUND_END`。
- **结算必须原子**：任何动作非法都必须在**改动棋盘之前**被拒绝；一旦拒绝，棋盘、`submittedEffectSeats`、`pendingEffectActions` 必须与提交前完全一致，使该座位可安全重试。否则已生效的移动会在重试时被**重复施加**（例如马连走两步）。

### 3.6 进入下一轮

```http
POST /api/kingchess/games/{gameId}/next-round
→ 200 KingGameView
```

- 仅 `phase = ROUND_END` 时接受；执行 §2.5-1（刷新公棋）、§2.4-末（无棋可用检查）、`roundNo++`，回到 `PLACING`。
- 若刷新后已满足胜负条件，直接 `FINISHED`。

```jsonc
  "players": [ KingPlayerView, ... ],
  "fields": {                      // 键固定为 NORTH|EAST|SOUTH|WEST，值恒为长度 4 的数组

  },
  "court": { "PROVISION": 7, "SOLDIER": 5, "HORSE": 4, "CHARIOT": 4, "KNIGHT": 2 },
  "submittedSeats": [0],           // 本轮已提交部署的座位
  "submittedEffectSeats": [],      // EFFECTS 阶段已提交动作的座位
  "lastRolls": { "0": 17, "1": 4 },// 座位号字符串 → d20 点数
  "lastDropOrder": [0, 1],         // 座位号，先落者在前
  "events": ["Player 0 ..."],      // 最近一次结算的事件日志（英文，前端可展示）
  "eliminatedSeats": []
}

// KingPlayerView
{
  "seat": 0,
  "side": "NORTH",
  "score": 0,
  "kingLives": 5,
  "eliminated": false,
  "hand": ["KING", "QUEEN", "MARTYR", "STRATEGIST"]   // 手牌中的棋子种类，可重复
}

// PieceView
{
  "id": 12,                 // long，全局唯一、稳定
  "kind": "SOLDIER",
  "ownerSeat": 0,           // Integer|null（棋局中的公棋为 null）
  "dropOrdinal": 3          // long，落子序；棋局/手牌中的棋子为 0
}
```

## 5. 前端交互契约（`ChessView.vue`）

1. **未开局**：显示人数选择（2/3/4）与「开始对局」，调用 3.1。
2. **PLACING**：左侧棋盘可点选格子；右侧「当前操作座位」面板列出手牌，选中棋子后点格子 = 记一次待落子；再点已记的格子可撤销。前端只校验**当前座位自己**的重复占格，**允许不同座位落到同一格**（结算时后落吃先落）。待落子**只存在于前端本地状态**（后端响应里没有，见 §3.3 保密条款），`submittedSeats` 只用来判断谁已提交。逐座位提交（调用 3.3），全部**在场**座位提交后出现「结算本轮」（调用 3.4）；出局座位不可被选为操作座位；切换座位时清空本地待落子。
   - 待落子只在本地暂存，提交前**不显示其他座位**的落子。热座下用「切换座位」避免偷看。
3. **RESOLVING/EFFECTS**：展示 d20 点数与落子顺序（3.4 的 `lastRolls` / `lastDropOrder`）。
4. **EFFECTS**：顶部显示 **16 秒倒计时**；列出当前座位可执行的效果动作；提交（3.5）；倒计时归零自动以空动作提交。
   - `DEFAULT-12`（**M1 热座适配**）：设计文档 §2 写的是「全玩家**统一**至多 16 秒」，那是面向 M2 在线多人的（所有玩家同时在窗口内行动）。M1 是**热座** —— 所有座位由同一人依次操作，若共用一个窗口，排在后面的座位必然被自动空提交、根本无法操作。因此 M1 采用**每个操作座位一个独立 16 秒窗口**；**M2 在线化时必须改回全局统一窗口**。
5. **ROUND_END**：事件日志 + 分数变化，出现「下一轮」（3.6）。
6. **FINISHED**：显示胜者与终局分数。
7. 棋盘渲染须体现：四棋场环绕中央棋局（棋局显示剩余公棋计数）、每格最多一子、棋子颜色区分归属、空格可放置。
8. 所有裁决信息（分数、命数、吃子结果、胜负）**只来自响应**，前端不自行推导。
